# Melodic review — September 10, 2026

Scope: `@melodicdev/core` (working tree, containing the unreleased 3.1.1 hardening pass on top of 3.1.0) and `@melodicdev/components` 3.1.0. Five parallel read-only audits (reactivity, core services, components A/B, DX + DevTools), with the lead independently reproducing the highest-impact claims. Items marked **[repro]** were confirmed by a scratch vitest run; the rest were verified by reading the full code path. No implementation files were changed by this review.

Severity: **P1** = fix before the next release. **P2** = next hardening pass. **Perf** / **DX** as labelled.

## 0. Blocker in the uncommitted 3.1.1 work

**R1. P1 [repro] — `computed()` with direct subscribers permanently loses source tracking.** ✅ **Fixed 2026-09-10** (dedicated notifier runnable in `computed.function.ts`; five regression tests in `tests/unit/signals-scheduler.test.ts`).
`src/signals/functions/computed.function.ts:74-87`, `src/signals/classes/signal-effect.class.ts:99`.
The tracker's `runNow()` calls `clearDependencies()` before `execute()`, and `execute()` only recomputes when `dirty`. If the computed is read between invalidation and the flush (a read inside `batch()`, or an earlier effect in the same flush reading it), the read recomputes and clears `dirty`; the scheduled tracker run then drops every source subscription and never re-adds them.

```ts
const a = signal(1); const c = computed(() => a() * 10); c.subscribe(f);
c(); batch(() => { a.set(2); c(); }); a.set(3);
c(); // 20 forever; f never fires again
```

This passes on HEAD (3.1.0) and fails on the working tree: it is a regression of the ASTRA #2/#3 fix. Fix: give computeds their own notification runnable (`if (dirty) recompute(); if (!Object.is(lastNotified, value)) notify`) and never route the tracker through `SignalEffect.runNow()`; `recompute()` must be the only place that clears dependencies. Add the repro above to `tests/unit/signals-scheduler.test.ts`.

## 1. Core: signals, template, components

**R2. Usability [repro] — templates do not track signal reads; only signal-typed component fields re-render.**
`src/components/classes/component-base.class.ts:312-333` (`render()` sets no active effect), `:417-419` (only fields holding a Signal/AbstractControl subscribe).
A template that reads `this.auth.user()` from an injected service, a signal inside a plain object, or a signal in an array never re-renders when it changes. Every comparable signal framework (Solid, Lit signals, Vue, Angular signals) auto-tracks reads during render. Fix: run the template inside a `SignalEffect` whose `onInvalidate` is `scheduleRender()`; then the field scanning in `observe()` becomes a fallback rather than the mechanism. This is the single largest usability improvement available.

**R3. Perf [repro] — every component renders twice on mount; `repeat()` children render twice.**
`component-base.class.ts:150, 208, 358-370, 450-456`. Initial `attributeChangedCallback` and `.prop=` writes from the parent template call `scheduleRender()` before connect; `connectedCallback` renders synchronously, then the queued microtask renders again. A 3-item repeat rendered 6 item templates. Fix: a `_dirty` flag set by `scheduleRender()` and cleared by `render()`; the microtask skips when clean.

**R4. P2 [repro] — an element re-attached after teardown is a zombie.**
`component-base.class.ts:186-193, 255-284, 534-547`. `teardown()` disposes parts but leaves `__parts`/`__templateKey` on the root; on reconnect `subscribeReactiveSources()` returns early (`_destroyed`), and `commit()` skips unchanged handler identities, so `@click` never re-attaches and `onCreate` does not refire. Fix: clear `__parts`/`__templateKey` in teardown and either re-initialise on reconnect or warn in dev.

**R5. P2 [repro] — text after `word=` is parsed as an attribute binding and leaks the marker as visible text.**
`src/template/classes/template-result.class.ts:363, 394-407`. `html\`<p>Total=${n}</p>\`` renders "Total=__m…_0__" in production. The regex runs on raw HTML with no in-tag state. Fix: only take the attribute branch when the cursor is inside an unclosed open tag.

**R6. P2 [repro] — quoted special bindings (`@click="${h}"`, `.value="${v}"`, `?disabled="${b}"`) emit a stray `"` attribute.**
`template-result.class.ts:389-411, 598-633`. The preprocessor strips the opening quote but keeps the closing one, yielding `__event-0__="""`; browsers create an attribute literally named `"`. `web/example/components/test/test.component.ts:13-15` uses this form. Fix: track the quote as the plain-attribute path already does.

**R7. P2 [repro] — a directive inside a composite attribute drops every other segment.**
`template-result.class.ts:720, 1310-1319`. `class="card ${classMap(...)}"` renders `class="active"`. Fix: warn in dev, or apply static segments before the directive runs.

**R8. P2 leak [repro] — duplicate keys orphan DOM and undisposed part trees in `repeat()` and keyed arrays.**
`src/template/directives/builtin/repeat.directive.ts:127-140`, `template-result.class.ts:951-970`. `oldItemsByKey.set` collapses duplicates; the shadowed item is neither reused nor removed. Fix: dev warning on duplicate keys; track old items by identity.

**R9. P2 leak [repro] — `computed()` (or any `registerDisposable` caller) created during render accumulates per render.**
`computed.function.ts:183`, `component-base.class.ts:313-317`. `select()` has an epoch sweep; `computed()` has none. Measured 21 disposables after 20 updates. Fix: warn in dev when created while `_rendering`, or apply the select sweep.

**R10. P2/DX [repro] — `observe()` host accessors shadow native element properties** (`hidden`, `title`, `id`, `slot`, `dir`, `tabIndex`). `component-base.class.ts:484-490`. A field `hidden = false` makes `el.setAttribute('hidden','')` leave `el.hidden === false`. Fix: warn and skip host exposure when `prop in HTMLElement.prototype`.

**R11. DX [repro] — no render-loop guard.** `component-base.class.ts:358-370`. A property write in `onRender` re-renders forever via microtasks (50 renders measured in one macrotask). Signals have a 100-iteration guard; components have none.

**R12. DX — `SignalEffect.run()` during a flush defers the first run** (`signal-effect.class.ts:43-46`), so code after `effect.run()` inside a subscriber sees it not yet executed. Blocks a predictable `effect()` helper. Also no `untracked()`.

**R13. DX — observed attributes are never validated.** `component-base.class.ts:198-209`, decorator `:82`. `attributes: ['count']` on `count = signal(0)` overwrites the signal with a string; `attributes: ['myAttr']` never fires (names are lowercased). Warn in dev.

**R14. P2 — `applyGlobalStyles` never handles a rejected load** (`src/components/styles/apply-global-styles.function.ts:13-44`): cross-origin `cssRules` throws, every later constructor produces an unhandled rejection; styles added after first construction are never adopted.

**R15. Perf minor — `repeat()` allocates an unused `keyToIndex` Map per render and calls `keyFn` 2-3 times per item** (`repeat.directive.ts:98-190`). `getAttributeValues()` builds an object per render though one template uses it (`component-base.class.ts:526-532`).

**R16. DX — `.value=${x}` skips the write when `x` is unchanged** (`template-result.class.ts:1250`), so a user-edited input cannot be reset to the same bound value; no `live()` directive. The destroyed-signal message says signals die with their component, but `signal()` never registers with one (only `computed()`/forms/`select()` do).

**R17. DX — `@MelodicComponent` silently ignores a second class registered under an existing selector** (`melodic-component.decorator.ts:56`). Warn in dev.

## 2. Core: routing, HTTP, DI, forms, state, bootstrap, config

**S1. P1 — a guard redirect bypasses every guard on the redirect target.**
`src/routing/services/router.service.ts:289, 338, 371, 599, 630`. A guard returning a string triggers `navigate(target, { skipGuards: true })`, skipping the target's `canActivate` and the current `canDeactivate`. A guard that redirects into a protected route opens it. Fix: drop `skipGuards`; bound redirects with a depth counter (S2).

**S2. P1 [repro] — route-level `redirectTo` chains are unbounded.**
`router.service.ts:351-358`. `{a → /b, b → /a}` (or `{path:'a', redirectTo:'a'}`) recurses forever in microtasks; the test worker died with heap OOM. Fix: `redirectDepth` through `navigate`, fail after ~10 hops with the chain in the message.

**S3. P1 [repro] — disabled controls still make the form invalid.**
`src/forms/classes/abstract-control.class.ts:65`, `form-group.class.ts:238-241`, `form-array.class.ts:227-229`. `value()` excludes disabled children but `invalid` does not, and `disable()` never clears errors; a disabled `required` field blocks submit forever. Fix: `invalid = !disabled() && (errors() !== null || children.some(c => !c.disabled() && c.invalid()))`.

**S4. P1 — same-component route param changes are silently stale.**
`src/routing/components/router-outlet/router-outlet.component.ts:290-293`. `renderMatch` returns early when the tag is unchanged, so `/users/1 → /users/2` neither recreates nor re-renders the leaf; `onCreate` (the documented place to read params, `docs/ROUTING.md:153-161`) never re-runs. Fix: expose `params`/`resolvedData` as signals on `RouterService` and document reading them in templates, or recreate when params differ.

**S5. P2 [repro] — `queryParams` are appended after the hash** (`router.service.ts:316-320`, `router-link-core.class.ts:94-97`): `/docs#intro?q=1`.

**S6. P2 [repro] — parametrised `redirectTo` never redirects, and a component-less match leaves the previous page on screen** (`match-route-level.function.ts:41`, outlet `:289-321`).

**S7. P2 [repro] — guard redirects inherit the caller's `queryParams`, `data`, `replace`** (`router.service.ts:339, 372`): `/login?tab=users`.

**S8. P2 [repro] — same-URL navigation pushes duplicate history entries and re-runs resolvers; hash-only popstate re-runs the whole pipeline** (`router.service.ts:312-396, 588`).

**S9. P2 — a blocked popstate overwrites the wrong history entry** (`router.service.ts:602, 634`): `[A,B,C]` with a blocked back from C becomes `[A,C,C]`. Fix: index in `history.state` and `history.go(delta)`.

**S10. P2 — hash scrolling cannot reach routed content and there is no scroll restoration** (`router.service.ts:403-412`): `getElementById` never searches shadow roots; `scrollRestoration` left on `auto`.

**S11. P2 — sibling outlets are detected as parent; outlet `name` is dead** (`router-outlet.component.ts:143-149, 187`).

**S12. P2 [repro] — non-JSON body on a JSON-typed error response becomes `NetworkError`** (`http-client.class.ts:338-365`): a 502 HTML page loses its status; retry/auth interceptors keyed on `HttpError` never fire.

**S13. P2 [repro] — `updateOn` semantics inconsistent** (`form-control.class.ts:25-27`, `form-group.class.ts:30-38`, `form-control.directive.ts:58-65`): programmatic `setValue` skips validation unless `updateOn: 'change'`; aggregates ignore their own `updateOn`; the directive writes the model on every input regardless.

**S14. P2 [repro] — `dispatch(key, action)` applies the first matching reducer, `dispatch(action)` applies all** (`signal-store.service.ts:107, 176-183`).

**S15. P2 leak [repro] — `select()` outside a component retains one computed per call** (`signal-store.service.ts:74`): 100 guard calls add 100 dependents to the state signal. Fix: `store.snapshot()` untracked read; document destroy.

**S16. Perf — resolvers on one route run serially** (`router.service.ts:555-557`). Use `Promise.all` per depth.

**S17. Perf — `RouteMatcher` regexes rebuilt for every route on every match, several matches per navigation** (`match-route-level.function.ts:39`). Cache in a `WeakMap<IRoute, RouteMatcher>`.

**S18. DX — no navigation event stream** (`router.service.ts:588-657`): no start/end/cancel/error, so a progress bar or resolver-failure toast cannot be built. Already on `docs/ROADMAP.md`; it is also the backbone of DevTools (§4).

**S19. DX — `@Service` getter has no setter** (`service.decorator.ts:9-24`), so tests cannot assign a fake; `bind()` silently replaces a resolved singleton; no optional injection; effect classes resolved lazily at first dispatch.

**S20. DX — `createValidator` mutates the global message registry** (`create-validator.ts:9-28`); built-in validators typed `ValidatorFn<string>` reject `FormControl<string | null>`.

**S21. DX — config/bootstrap gaps**: `environment.ts:8-16` ignores Vite `MODE` (`--mode qa` resolves to prod); `bootstrap.function.ts:128-135` calls `onReady()` before binding `IMelodicApp`; `IMelodicApp.http` never populated; `RouterService` news up `RouteContextService` so `Injector.get(RouteContextService)` is a different empty instance.

### Cross-component consistency

- **Active-state prop**: tabs `value`, steps `active`, sidebar `active`, pagination `page`.
- **`ml:close` timing**: drawer fires before its animation (plus `ml:opened`/`ml:closed`), dialog after native close with `{result}`, popover/dropdown/select on toggle.
- **Open-state API**: no `open` attribute on dialog/drawer/popover/dropdown; date-picker `toggleCalendar`, time-picker `togglePopover`; select/autocomplete/popover/dropdown expose an undocumented writable `isOpen`.
- **Reopen guards**: `ToggleDismissGuard` (popover/dropdown), a 150 ms timestamp (select), `popover="manual"` plus a document listener (autocomplete), raw `autoUpdate` (time-picker).
- **Size types**: `Size` (xs–xl) vs `ControlSize` (sm–lg) vs local `ProgressSize`/`HeroSize`; `select.styles.ts` only styles `--sm`.
- **Change detail shapes**: `{checked}`, `{value, checked}`, `{value, option?}`, `{value}`/`{values}`; slider/input/textarea adapters pick `ml:input`, others `ml:change`.
- **Slot-presence detection**: `watchSlotPresence` (card, divider, page-header, page-section), live getters (sidebar, login, signup, calendar-view), `MutationObserver` (dashboard-page).
- **Router integration**: tabs/steps via `RouterService`; sidebar/breadcrumb/page-section via raw anchors.
- **Panel visibility**: tabs/steps set inline `style.display` on light-DOM panels instead of `hidden`.
- **Locale**: date-picker hardcodes MM/DD/YYYY; calendar-view hardcodes `en-US`; weekday/month names are English constants.
- **Missing common props**: `ml-input` lacks `name`/`maxlength`/`min`/`max`/`pattern`/`inputmode`; `ml-checkbox` lacks `name`/`value`; autocomplete `minChars`/`debounce`/`showIcon` are property-only.
- **Positioning**: `flip()` tests only main-axis overflow against the viewport and keeps the original placement when nothing fits; `shift()` ignores clipping ancestors.

Checked and clean: `autoUpdate`, `VirtualScroller`, focus trap, click-outside and tooltip timers all clean up; `applyTheme('system')` removes its previous listener; `injectTheme` replaces rather than accumulates; the dark preset covers every light key; app-shell and dashboard-page observers disconnect.

## 4. Developer experience and DevTools

### DX findings (ranked)

**D1.** `html` bindings are untyped: `@click=${'not a function'}` and `.value=${1}` type-check clean (`html.function.ts:3`).
**D2.** `@Service` is untyped: `@Service(A) svc!: B` compiles (`service.decorator.ts:4-5`). Add `inject<T>(token): T`.
**D3.** Route params are `Record<string,string>` everywhere; no path-string inference.
**D4.** `provideRouter` is undocumented and unused by the example and CLI; `web/example/main.ts:1-6` deep-imports internals with an incorrect import-order comment.
**D5.** No component-testing story: nothing test-related is exported; every test hand-rolls `flushMicrotasks` and mount/unmount. Add `@melodicdev/core/testing` with `mount`/`flush`/`unmount` and a `docs/TESTING.md`.
**D6.** 85 hand-rolled `dispatchEvent` sites in the components package; `docs/COMPONENT_SYSTEM.md:663-668` tells users to write their own helper. Add `emit(host, name, detail)` with `bubbles/composed` defaults and a typed event map on `TypedComponentMeta`.
**D7.** Attribute→property coercion is heuristic by default; `static propertyTypes` is used by 1 file while 71 declare `attributes`. Accept `attributes: { open: 'boolean' }` and warn when an observed attribute lands on an untyped property.
**D8.** No `effect()` helper; the CLI scaffold models derived data as plain functions called 5+ times per render and never shows `computed()` (`packages/cli/templates/app-basic/src/components/app.component.ts:326-339`).
**D9.** CLI scaffold hardcodes `devMode: true` and its tsconfig lacks `vite/client` types.
**D10.** Docs/code mismatches: README and CLAUDE.md omit `onConnect`/`onDisconnect`; CLAUDE.md shows `component: HomeComponent` and `guards:` but the fields are a tag string and `canActivate`; `COMPONENT_SYSTEM.md:429` says disposables die on `disconnectedCallback` (they die in the deferred teardown); `STATE.md:81-95` documents `implements ActionEffects` while the example uses `extends EffectsBase`, which has zero doc mentions.
**D11.** ~35 public exports with zero doc mentions (`installHistoryEvents`, `RouteMatcher`, `RouterLinkCore`, `setActiveEffect`, `setActiveComponent`, `disposeParts`, `AbortError`, `NetworkError`, `EffectsBase`, …). Document or move to an `/internal` entry.
**D12.** Error messages: the destroyed-signal error, the circular-effect error and `Disposable cleanup failed` carry no owner/name; guard and load errors carry no route path; prefixes vary (`[Melodic]`, `[melodic]`, `[HttpClient]`, `[SignalStore]`, none).
**D13.** Two-way input binding is manual boilerplate everywhere (`.value=` + `@input=` + a casting handler). A `:model=${signal}` directive can reuse the forms adapter registry.
**D14.** Three separate dev/prod switches: `bootstrap({ devMode })` (default false, gates only bootstrap logs), `import.meta.env.DEV` (template diagnostics), `import.meta.env.VITE_ENV`/`PROD` (config, read at module load). Both prebuilt `bundle/` files fold `isDevMode()` to false, including the "development" one.

### DevTools: proposed design

One `window.__MELODIC_DEVTOOLS_HOOK__` object, created lazily by the framework in dev or pre-installed by an extension content script. Shape:

```ts
interface MelodicDevtoolsHook {
  version: string;
  emit(event: HookEvent): void;
  on(type: HookEvent['type'] | '*', fn: (e: HookEvent) => void): () => void;
  components: Map<number, { id; selector; host: WeakRef<ComponentBase>; parentId; renders; lastRenderMs }>;
  signals: Map<number, { id; kind: 'signal' | 'computed' | 'effect'; name?; ownerComponentId? }>;
  bindings(): Array<{ token: string; type; singleton; resolved }>;
  router: { current(): IRouteMatchResult | null };
  store: { state(): unknown; history: Array<{ ts; action; before; after }> };
}
```

Events: `component:define|create|connect|render|disconnect|destroy`, `signal:create|set|destroy`, `computed:recompute`, `effect:run`, `flush:start|end`, `nav:start|end|blocked|error|superseded`, `store:dispatch`, `di:bind|resolve`.

Framework changes, all behind one `__DEV__` boolean plus a null-hook check (one boolean and one null check per emit site when no DevTools is attached; registries populate only after `hook.on()` is first called; branches fold away in prod builds):

1. `src/devtools/dev-mode.ts` (new): the single `__DEV__` source; migrate the six `isDevMode()` sites in `template-result.class.ts`; `bootstrap({ devMode })` defaults to it.
2. `src/devtools/hook.ts` (new): id counters, `emit()` no-op fast path, registries.
3. `component-base.class.ts`: emit in constructor, `connectedCallback`, `render()` (wrapped in `performance.now()` only when a hook is present), `disconnectedCallback`, `teardown()`. Add public `debugInfo()` returning selector, reactive props and source props.
4. `melodic-component.decorator.ts:88`: push `{selector, cls}` into a registry; emit `component:define`; warn on duplicate selector (R17).
5. `signal.function.ts` / `computed.function.ts`: optional `{ name }` option; emit `signal:create` with `getActiveComponent()` as owner and `signal:set` after the equality check; value-export `DEPENDENTS` or a `getDependents(sig)` helper. The `name` also fixes D12 for free.
6. `batch.function.ts:97`: emit `flush:start/end`.
7. `signal-effect.class.ts:74`: emit `effect:run`; accept `{ name }`.
8. `router.service.ts`: the S18 event stream as a public `events` signal; the hook subscribes to it.
9. `signal-store.service.ts:83`: emit `store:dispatch` with before/after snapshots when a hook is attached; make `getCurrentState()` public as `snapshot()`.
10. `injection-engine.class.ts`: add `entries()`; emit `di:resolve`.
